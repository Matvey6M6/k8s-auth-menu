# @mmmatvey122/k8s-auth-menu

Пакетная аутентификация в нескольких кластерах Kubernetes / OpenShift из UI OpenLens.

## Возможности

- свой список кластеров с галочками, группами и inline-редактированием;
- **последовательный** логин с индивидуальным статусом по каждому кластеру, паузой между
  кластерами и повторами при ошибке;
- живой лог процессов с маскированием пароля;
- запись токенов в стандартный `~/.kube/config` (по умолчанию) либо в отдельный файл;
- импорт/экспорт списка кластеров в JSON;
- страница настроек в Preferences, проверка бинарника `login --help`;
- вход из статус-бара, пункт на экране Welcome и команда в Command Palette (`Ctrl+Shift+P`).

Пароль **не** сохраняется ни в конфиге, ни в логах.

> Логины идут строго по одному: все они пишут в один и тот же kubeconfig

## Требования

- OpenLens 6.x (API расширений `^6.0.0`);
- Node.js 18+ и npm — только для сборки;
- CLI с подкомандой `login`: `oc` или `kubectl` с плагином `kubectl-login`.
  Ванильный `kubectl` подкоманду `login` не имеет.

## Установка

```bash
npm install
npm run pack-extension     # clean + build + npm pack
```

Получится `mmmatvey122-k8s-auth-menu-1.0.0.tgz` — далее
**Extensions → Install from file** (или перетаскиванием в окно OpenLens).

OpenLens распакует пакет в `~/.k8slens/extensions/mmmatvey122--k8s-auth-menu`
(`@` убирается, `/` превращается в `--`) и включит расширение автоматически.


## Где точка входа

OpenLens 6.5 Вход на страницу сделан через `statusBarItems`:

| Куда нажать | Что это |
|---|---|
| **k8s Auth** в статус-баре, правый нижний угол | основная кнопка, `statusBarItems` |
| Пункт на экране Welcome | `welcomeMenus` |
| `Ctrl+Shift+P` → *открыть страницу логина* | `commands` |

Если пункта в статус-баре нет — расширение не загрузилось; смотрите **Диагностику**.

## Первый запуск

Список кластеров изначально **пустой**.

1. **Preferences → k8s Auth** — путь к `kubectl` (кнопка «Найти автоматически»),
   при необходимости `--insecure-skip-tls-verify`, паузы и повторы.
2. Пункт **k8s Auth** в статус-баре (правый нижний угол) → **Добавить** (или **Импорт**, если список
   уже кто-то собрал) → заполнить имя и URL.
3. Отметить нужные кластеры галочками, ввести логин/пароль → **Login**.
4. По умолчанию токены пишутся в `~/.kube/config`, который OpenLens синхронизирует сам.
   Отдельный **Preferences → Kubernetes → Kubeconfig Syncs** нужен, только если
   в настройках выбран свой путь.

### Кнопки над списком

| Кнопка | Что делает |
|---|---|
| Добавить | новая пустая строка, невыбранная |
| Выбрать все / Исключить все | ставит или снимает все галочки (при активном фильтре — только в этой группе) |
| Удалить выбранные | удаляет отмеченные галочкой кластеры, с подтверждением |
| Экспорт / Импорт | список целиком в `~/.k8s-auth-menu/clusters-export.json` и обратно |
| Очистить kubeconfig | вычищает целевой kubeconfig до пустого файла, с подтверждением |


> «Очистить kubeconfig» удаляет из файла **все** кластеры, контексты и пользователей, а не
> только заведённые расширением. В режиме по умолчанию цель — общий `~/.kube/config`.
> Резервная копия по умолчанию **не** создаётся: в kubeconfig лежат действующие токены,
> и лишний дубль рядом с оригиналом сводит смысл очистки на нет. Если копия всё же нужна —
> в диалоге есть отдельная галочка, и удалять файл `config.bak-<дата>` придётся вручную.

## Где что лежит

| Что | Путь |
|---|---|
| Настройки и список кластеров | `~/.k8s-auth-menu/config.json` |
| Экспорт кластеров | `~/.k8s-auth-menu/clusters-export.json` |
| Лог последнего прогона | `~/.k8s-auth-menu/last-run.log` |
| Токены (kubeconfig) | `~/.kube/config` (настраивается) |
| Логи OpenLens | `%APPDATA%\OpenLens\logs\` |

## Диагностика

| Симптом | Причина / решение |
|---|---|
| Нет пункта «k8s Auth» в статус-баре | расширение не загрузилось: `%APPDATA%\OpenLens\logs\lens.log`, строки `EXTENSION-DISCOVERY` / `EXTENSIONS-LOADER` |
| `can't load extension manifest ... reading 'match'` | в каталоге расширений лежит папка без `engines.lens` в `package.json` — удалите её |
| `can't load renderer ... Cannot find module 'react'` | `react` не вынесен в externals; в `webpack.config.js` должно быть `react: "var global.React"` |
| `unknown command "login"` | ванильный kubectl — укажите `oc.exe` или поставьте `kubectl-login` |
| `spawn ENOENT` | неверный путь к бинарнику; проверьте кнопкой «Проверить kubectl» |
| Кластер отмечен, но не участвует в прогоне | некорректный URL (нет хоста) — поле подсвечено красным |
| Логин успешен, кластеров нет в каталоге | выбран свой путь kubeconfig без Kubeconfig Sync |
| `x509: certificate signed by unknown authority` | включите `--insecure-skip-tls-verify` или добавьте корпоративный CA в систему |
| Два одинаковых пункта в Extensions | осталась установка под старым именем — удалите её |
| Ошибки типов при сборке | `transpileOnly: true` включён, сборка не падает из-за типов; смотрите вывод webpack |

## Формат JSON для импорта

```json
[
  {
    "name": "prod-01",
    "url": "https://api.prod-01.example.com:6443",
    "enabled": true,
    "group": "PROD"
  }
]
```

`id` можно не указывать — сгенерируется автоматически.
Записи без хоста в `url` (например `https://`) при импорте отбрасываются.

## Замечание по безопасности

Пароль не пишется ни в один файл: он живёт только в состоянии страницы и передаётся
в CLI. В лог и в UI он попадает уже замаскированным (`mask()` в `kubectl.ts`).

Чего это не отменяет:

- при выключенном «Передавать пароль через stdin» пароль уходит в **аргументы процесса**
  и виден в Sysmon / Event 4688 / EDR, то есть уезжает в SIEM. Если ваш CLI умеет читать
  пароль из stdin (`oc login -u user` без `-p`), включите чекбокс в настройках;
- `--insecure-skip-tls-verify` отключает проверку сертификата: MITM между вами и API-сервером
  сможет перехватить и пароль, и выданный токен.;
- долговременный секрет здесь не пароль, а **токен** в kubeconfig. Он лежит в файле
  с правами вашей учётной записи и живёт часами.
